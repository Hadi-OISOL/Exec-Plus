## Feature mapping

- Phase 1 improves existing data reading and onboarding (18/47), chat and visual
  exploration. Production signup/login remains a separate dependency for 1/40/47.
- Phase 2 improves current explanation/planning quality and internal checks for 44.
  Fictional tests cannot close representative model-quality acceptance.
- Phase 3 addresses internal logic within Partial 33/57/58/59. None is declared
  broadly complete from a bounded method. Read the advanced analytics research
  plan before selecting the next implementation and validation contract.
- Phase 4 provides internal evidence toward 44/50, not a production-quality or
  sustained-performance certification.
- External identity, billing, SMTP, off-server recovery, monitoring destinations,
  connectors and customer integration policies are outside today's two phases.
  Fine-grained permissions (64) need a dedicated policy/architecture design.

## Next-session implementation boundaries

Phase 3 adds comparisons that the existing group-contribution report does not
already provide. A user chooses two eligible measures and one category. Compare
the pooled relationship with relationships within groups, over the same covered
rows, and flag differing directions without claiming causes. Proposed bounds:
at least two eligible groups, twenty complete pairs per group, at most twelve
levels and the existing ten-thousand-row complete-population limit. Report
excluded rows and sparse/constant groups; refuse mismatched required filters.
Independent fixtures must include a pooled/within-group reversal, weak/no
relationship, uneven groups, missing values and exact receipt/privacy checks.

Allocation adds explicit prerequisites (“selecting A requires at least one B”)
and exclusions (“A and B cannot both be selected”). These are selection rules,
not scheduling or time precedence. Retain exact costs/benefits, both resource
limits, the hundred-thousand-combination cap and old saved versions. Validate
unknown/self constraints, declare cycle handling and compare small cases with
an independent exhaustive oracle, including conflicting requirements and the
feasible do-nothing baseline. No external action is executed.

Phase 4's fixed cases cover private/saved context, missing units/dates, malformed
readings, those new methods, source changes, cancellation and reopening. Check
1440/390/320 widths, keyboard and reduced motion. Record per-step latency, errors
and resources on the same declared fixture before/after; an eight-user internal
rehearsal does not establish sustained production performance. Advanced scenario
uncertainty and seasonal/multivariate/drift anomalies remain open unless their
separate evidence contracts are implemented and verified.
