# Personal data assistant and refreshed workspace

The user requested data that demonstrates Syntelio well, memory for each user,
research into Google's data agents and a visibly better interface. This slice
extends the existing private demo; it does not replace its model provider or
enable a Google connector. The original 64 feature IDs and production gates remain.

## Deliverables

1. Generate a clearly fictional retail dataset with complete dates, declared
   units, sufficient group sizes, meaningful relationships and unusual records.
   Generate a separate small action table for allocation. Supply easy questions,
   exact setup instructions and independently checked expected results. Keep CSV
   artifacts ignored; commit reproducible generators and tests. Offer the samples
   through the existing sample-import flow, with explicit definition review.
2. Add explicit actor-private memory within a workspace, separate from shared
   dataset meanings and dataset-specific goals. Users can view, edit and forget
   context. New qualitative readings and
   starter suggestions receive bounded remembered context, with current questions
   and dataset meaning taking precedence. Personal memory is excluded from numeric
   planning and its advisory selector, so it cannot introduce new hidden filters. No silent learning from all
   conversations or automatic confirmation of business facts is introduced.
3. Refresh the workspace into a lighter, more spacious analytics studio. Give
   questions, source context, results and optional detail a clear visual order.
   Preserve working navigation, exact values, accessible controls, responsive
   layouts, reduced motion and current evidence/privacy boundaries.
4. Verify sample eligibility, memory reuse/isolation/deletion and actual browser
   journeys. Build and release only after checks, with a checked backup, migration
   preservation evidence, rollback checkpoint and live verification.
5. Repair the reported confirmed-version-three missing-unit workflow: inspect
   retained definitions, target answers to the correct field, preserve descriptions
   and drafts, distinguish saving from reloading, and prove persistence after reopen.
6. Download the requested repositories locally, install relevant project skills,
   inspect their source/license fit and apply suitable design/analysis guidance.
   Keep Lieflat's noncommercial template workflow as an inactive reference and
   implement original chart improvements. Record scanner findings and their limits;
   downloaded skills do not become unrestricted runtime tools.

## Agent tools and research interpretation

Syntelio already has a bounded conversation plan containing profile inspection,
validated queries, document retrieval, pattern exploration, group comparison and
evidence assembly. Forecasts, scenarios, anomalies and allocation use dedicated
validated services and explicit inputs. A tool's description does not authorize
arbitrary code, network access, source writes or missing assumptions.

Google's public documentation describes data agents combining selected knowledge
sources, descriptions, instructions and verified queries. Its insights feature
suggests questions/queries and descriptions grounded in metadata and profiling.
These are useful patterns for strengthening our existing definitions and tools;
they are not evidence that an unrestricted agent is required.
[Conversational analytics](https://docs.cloud.google.com/bigquery/docs/conversational-analytics),
[data insights](https://docs.cloud.google.com/bigquery/docs/data-insights).

Google Data Canvas documents a staged find → query → visualize workflow, with
iterative questions and chart details. Our simpler workspace keeps those actions
discoverable without adding a graph editor. Public illustrations and docs do not
establish private backend behavior or comparative answer quality.
[Data Canvas](https://docs.cloud.google.com/bigquery/docs/data-canvas).

Google ADK documents tools and longer-term memory as separate capabilities.
Syntelio retains its existing provider-neutral services and PostgreSQL rather
than adding a second orchestration framework or memory vendor for this slice.
[ADK custom tools](https://adk.dev/tools-custom/),
[ADK memory](https://adk.dev/sessions/memory/).

## Acceptance and limits

- Generated samples exercise real parser, meaning, query and analysis contracts;
  successful fictional examples do not establish general model accuracy.
- Memory is scoped by workspace and actor, with conflicts and revocation checked.
  Clearing active memory does not silently rewrite immutable old conversations or
  erase retained backups; the UI must state the actual behavior.
- New storage must preserve existing tables and historical receipts. No database
  restore is used as an application rollback that would erase newly saved work.
- Compare before/after screenshots and complete desktop/mobile flows. Record
  actual pass/fail/skip counts, including model-dependent limitations.
- No production gate, broad advanced-method status, connector or competitor parity
  is promoted merely because this slice succeeds.

The delivered behavior is recorded in [the contract](personal-agent-studio.md).
Actual checks, failed attempts, release preservation and remaining limitations
are recorded in [the verification ledger](verification-personal-agent-studio.md).
This plan defines scope; the ledger supplies completion evidence.
