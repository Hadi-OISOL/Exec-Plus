# Guided analysis gap audit — October 13

The overview mounts the ask-first hero, guided review, discovery and conversation together after upload. The hero persists after data selection. Analysis intent is a separate dropdown and private goals are a separate upload field. A user cannot follow one clear sequence from intent to results.

The existing deterministic discovery engine already calculates descriptive findings. Forecasting and decision analysis already have governed APIs and immutable results. Forecasts require declared complete date coverage; allocation requires explicit costs, benefits, budget and assumptions. These declarations must remain user-owned. Quick review covers at most ten columns and cannot confirm an entire wide schema.

Implement a focused intent → personal context → data review → results journey. Do not mount discovery/chat while the journey is open. Retain full definition review when corrections need confirmation. Preserve optional quick notes/drafts and permission/version checks. Descriptive results can execute automatically after review; forecasting and allocation must collect their required declarations through existing governed controls. All-supported means available methods, not a promise that every file supports every method. No migration, provider change or automatic external action is required.

Acceptance: no persistent hero during upload review; back navigation retains answers; private goal saving is explicit and preserves the existing domain; failed loading/saving can retry; source/account changes reset journey state; unconfirmed saved meanings block completion; descriptive findings load only after completion; unsupported forecast/allocation inputs remain explicit; existing saved work and direct navigation remain available.
