# Chart experience reference audit

Reviewed October 16, 2026. The user asked for these references to improve the actual
product. The immediate application work is the dashboard, calculated-answer charts,
measured-pattern cards and forecast presentation described in
[chart experience](chart-experience.md). This audit supplies design evidence and
acceptance requirements; it does not certify an unfinished release.

The pinned sources and licenses are recorded in [project skill adoption](project-skill-adoption.md).
Five selected skills are available locally to the coding agent after client
discovery. The application's agent continues to use its existing authorized
analysis tools. None of these repositories is registered as an unrestricted
runtime tool, and oneDAL is not installed in application images.

These screenshots show presentation, not backend behavior. A visible relationship
in a gallery example does not establish causation or predictive quality. A filled
or hollow marker can distinguish series without color, but its meaning must be
explicit in ExecPlus's own legend. A line is appropriate only when the returned
ordering and missing-value policy support a connection.

The [installed skill](https://github.com/larashero3-dotcom/lieflat-charts/blob/ed436ba56b3cbeee20b9b9966b38a9a9689e239c/SKILL.md)

template-copy instructions, token files and artwork are not used in the product.
The PolyForm Noncommercial boundary and unchanged partial static-scan result are
documented in [the Lieflat assessment](lieflat-charts-assessment.md).

## Application contracts for this change

The existing route remains: confirmed source meaning → eligible authorized tool →
deterministic result and source receipt → an allowed visualization. Personal
memory can guide a new qualitative explanation; it cannot supply missing units,
change a required filter or invent chart values. No model-generated HTML, SQL or
Python is executed to draw a result.

| Existing surface | Useful concrete improvement | Required invariant |
| --- | --- | --- |
| Dashboard | Clear reading order and more space around the real question, chart and evidence action; distinguish loading, empty and calculated states | Dashboard ownership, source selection, filters, saved results and their exact returned strings remain unchanged |
| Calculated answers | Direct bar/dot labels and a legible selected-value explanation; controls that work with keyboard and touch | Signed values, true zero, nulls, original order and precise numeric strings remain distinguishable. A changed chart does not rerun a different calculation |
| Measured patterns | Explain each chart's units and covered rows; keep stronger findings separate from weak comparisons; show pooled and within-group comparisons clearly | No forced finding, inferred causality, unreported sampling or hidden exclusions; numerical tables/receipts remain available |
| Forecasts | Separate observed points from estimates, preserve the uncertainty band and make period/value inspection easier | No line across a missing observation; no false precision in the band; if history is visually shortened, disclose that and retain complete exact tables |
| Scenarios and decisions | Reuse clear value/source presentation where shared components apply; keep baseline and supplied assumptions easy to identify | Assumed changes and additive benefits remain assumptions, not observed outcomes or causal predictions. This chart work adds no new scenario or allocation method |

Chart coordinates may use bounded approximate numbers for geometry. Exact tables,
point labels and inspectors retain original strings; axis and headline values may
group digits and trim insignificant trailing zeros without changing numeric value. A geometry fallback should
remain explicit; it must not erase a nonzero value, present a missing cell as zero,
or fabricate a ranking between values that cannot be plotted distinctly.

## Verification and release claims

The implementation owner records the final component changes and passing checks
in the release ledger. Useful acceptance cases include mixed positive/negative
bars, exact zero versus null, high-precision decimals, single-point/constant series,
missing dates, long category names, focused values on a narrow screen and reduced
motion. Existing drill-down, source/replay and read-only evidence behavior must
remain intact.

The fictional retail kit provides independent checks: total Revenue is
**8,235,156.60 USD**, total Orders is **141,464**, and a supplied +10% revenue
scenario is **9,058,672.26 USD**. Its pooled advertising/revenue relationship has a
different direction from the three within-region relationships; the display must
not flatten that distinction into a universal story. These are synthetic workflow
checks, not representative acceptance or proof of causality. The guide and tests
record the generator and exact definitions.

No new numerical method, provider, runtime package, schema, production gate,
connector or export feature is claimed by this audit. The user's earlier open-tab
mismatch remains unverified until their refreshed screen is observed; a successful
fresh-browser check alone does not diagnose their tab.
